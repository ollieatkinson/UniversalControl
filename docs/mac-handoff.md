# macOS Handoff

Please pull this repo and test the native backend on macOS.

## Checks Needed

1. Build:

   ```sh
   cargo check
   ```

2. Preflight the bridge configs:

   ```sh
   cargo run -- --config configs/receiver.example.toml preflight
   cargo run -- --config configs/input-owner.example.toml preflight
   ```

   Record the detected primary display, effective local display, peer mode, and
   warnings. On native macOS, a missing detected display is a useful bug report;
   on WSL it is expected.

3. Probe passive capture:

   ```sh
   cargo run -- probe listen --count 20
   cargo run -- probe listen-events --count 20
   ```

4. Probe grab without suppression:

   ```sh
   cargo run -- probe grab --count 20
   cargo run -- probe grab-events --count 20
   ```

5. Probe grab with suppression:

   ```sh
   cargo run -- probe grab --count 20 --suppress
   cargo run -- probe grab-events --count 20 --suppress
   ```

6. Probe injection:

   ```sh
   cargo run -- probe inject --key KeyA
   cargo run -- probe inject-mouse --x 200 --y 200
   cargo run -- probe inject-button --button Left
   cargo run -- probe inject-wheel --delta-y 3
   ```

7. Capture and replay normalized events:

   ```sh
   mkdir -p artifacts
   python scripts/capture-input-events.py --mode listen --count 20 \
     --jsonl artifacts/macos-input-events.jsonl \
     --output docs/observations/YYYY-MM-DD-redacted-macos-input-events.md
   cargo run -- --config configs/input-owner.example.toml probe route-events \
     --path artifacts/macos-input-events.jsonl \
     --expect-activation \
     --min-forwarded-inputs 1
   cargo run -- probe replay-events --path artifacts/macos-input-events.jsonl --dry-run
   cargo run -- probe replay-events --path artifacts/macos-input-events.jsonl --delay-ms 50
   ```

   The wrapper writes a redacted summary that omits typed text values. Run
   `route-events` when macOS is being tested as the input owner; it reports
   whether the captured pointer movement would activate the remote side and
   suppress local input, without native hooks or network. The expectation flags
   make the command fail when the capture does not cross the configured edge or
   forward any input. Run `--dry-run` first to validate JSON parsing and
   key/button mapping without injecting input. Only run full replay with a
   controlled foreground target. This proves the JSON generated by
   `listen-events` or `grab-events` can drive the same injector used by the
   receiver role.

8. Run as receiver with the Windows machine as input owner:

   ```sh
   cargo run -- --config configs/receiver.example.toml
   ```

9. Run as input owner with the Windows machine as receiver:

   ```sh
   cargo run -- --config configs/input-owner.example.toml
   ```

10. Record whether `rdev::grab` captures Keychron events.
11. Record whether returning `None` from the grab callback suppresses local keyboard and mouse delivery.
12. Record whether `rdev::simulate` injects key, pointer, click, and wheel events into normal apps.
13. Record whether replayed normalized JSON produces the same visible input as the one-shot inject probes.
14. Record whether normalized `InputEvent` JSON has the expected key names, text values, button names, pointer coordinates, and wheel deltas.
15. Record any `unsupported key name` or `unsupported mouse button name` replay/bridge errors exactly; these are intentional mapping-gap failures.
16. Record required macOS permissions and whether logout/restart was needed.
17. Record modifier behavior for Command, Option, Control, and Fn/function row.
18. Check whether Secure Input breaks capture in Terminal, password fields, browsers, and IDEs.

## Notes To Push Back

Add a dated note under `docs/mac-spikes/` with:

- macOS version.
- Keychron model and connection mode.
- Keyboard layout.
- Whether the Keychron is paired to one or both machines.
- Logs from both roles.
- Any changed code or mapping patches.
